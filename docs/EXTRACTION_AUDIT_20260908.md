# 数据提取复核：哪些已经进入，哪些还不能使用

这次核对的范围是当前保留家庭所对应的 SGSC 家庭主表 46 列，以及 iFlex Survey 1 的 96 列。每列都登记了来源、回答覆盖、保存位置和处理原因。“原始回答已保留”和“已进入模型输入”分别计数。

| 来源 | 来源列的处理结果 |
|---|---|
| SGSC，46 列 | 24 列进入画像；1 列活动产品信息由活动构造处理；1 列气候区代码已有文字描述；1 列为户号；19 列仅保留追溯并逐项说明原因。 |
| iFlex，96 列 | 88 列已建立画像映射；1 列为户号；7 列为无回答的第三辆电动车问题。88 列包括条件题和未知回答，不表示每户都有 88 项已知属性。 |

## 复核发现并修正的问题

| 问题 | 修正 |
|---|---|
| iFlex 新增五类供暖方式已经在 JSON，但活动表只展开旧设备；家庭表没有完整设备列表。 | 两份数据的活动表、家庭表均加入 `profile_appliances`，完整保留设备、数量、用途及原回答，同时补入新增供暖方式的展开列。 |
| 家庭表没有保留原简表中的气候区、假定房型、表计配置及 iFlex 区域。 | 补入原简表、表计配置和区域列；不把假定房型改称住户自报。 |
| iFlex 的无光伏、无农场或经营用电共表回答只在筛选和追溯中。 | 明确写入 `input.profile.energy_systems`；当前 314 户的这两项均为否。容量及光伏配套电池后续题没有回答，保留未知。 |
| SGSC 短信联系意愿只保存在原记录。 | 补入 `preferences.agreed_to_sms_contact`；当前 2,078 户均同意短信联系。这不是需求响应方案的接受标签，也不能用这个常量解释户间差异。 |
| SGSC 白天在家的适用日曾写为未明确。 | 原始字典明确为工作日正常工作时间，已修正为 `weekday_daytime`。 |

JSON 全量文件、两类表格和全部样例一起重建。候选成员、历史读数及目标电量沿用原批次；核验脚本另外比较每一条原始来源记录。

## 仍只保留作追溯的资料

SGSC 的反馈技术产品代码可能与用电行为有关，因此不能简单称为无关管理字段。当前第一项产品代码有 1,272 户非空，第二项有 80 户非空；尚未逐户确认各活动日前的实际启用状态及产品含义，暂未加入预测输入。这是待核实的信息，不是已完成提取即可直接训练的特征。

试验招募或分组标记、内部编号、服务状态、退出原因和办理日期保留追溯；它们不等同于生活习惯，部分还可能包含活动之后的信息。假定用电、用气等级的推断过程未确认，也不当作直接调查值。活动产品代码已由原活动构造保存在 `input.context`，不拿家庭主表状态覆盖它。气候区描述已经在输入中，数字代码无需重复解释为另一项特征。

iFlex 第三辆电动车的七项细节，在保留的家庭中全部无回答；这批家庭最多报告两辆，因此逐车列表没有虚构第三辆。年龄矛盾、明确未知及拒答仍按原清洗规则处理，不能为了“填满”画像而猜数。

## 这份审计能确认到哪里

可以确认这两张画像来源表的每一列都有明确去向，家庭表和活动表都保存了 JSON 中的完整画像。家庭成员、住房、设备、舒适偏好、一般使用习惯和能源关注等现有信息，已纳入相应结构。

还不能确认两份数据足以还原完整多电器家庭：SGSC 当前家庭主表没有人数、年龄和收入明细；iFlex Survey 1 缺少冰箱、洗衣机、洗碗机等完整持有清单。两者的问卷习惯也不是逐台设备在活动日的运行日志。本次没有把其他来源表、HAN 分表或其他问卷阶段全部审计完；不能把当前两张表的字段对账扩写成整个数据集无遗漏。

来源没有记录的设备和具体使用安排保留未知，本次未使用假设或仿真填补。SGSC 全量全天窗口、逐字段预测前可得时间以及最终 SFT 输入导出尚未完成。
